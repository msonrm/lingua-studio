# 実験結果: LinguaScript に実用的な価値はあるか

計画は [EXPERIMENT-PLAN.md](./EXPERIMENT-PLAN.md)。判定基準は実行前に固定してある。

## 結論

**LinguaScript に、曖昧さ解消の道具としての実用性は示せなかった。**

生成 AI は英語の構造的曖昧さを完璧に検出できる（18/18）。放っておくと指摘しないが
（3/18）、**「曖昧なら指摘して」と一行足すだけで回復する**（14/18、主要な種類では 6/6）。

事前登録した判定表の「**F が B と同等 → 不要。AI が聞き返せば済む**」に該当する。
一行の指示が上限に達している以上、LinguaScript を与えてもそれを超えられない。

---

## Phase 0: 英語にどれだけ曖昧さがあるか

AST を機械的に列挙し、同じ英語になる相異なる AST の組を集めた。曖昧な文は手で選んでいない。

| | 値 |
|---|---|
| 生成した AST（重複除去後） | 3,700 |
| 英語の相異なる表層 | 2,620 |
| 衝突グループ | 1,000（すべて2個組） |
| 衝突に関与する AST | 2,080（56%） |

### 内訳 — 英語の構造的曖昧さは2種類しかない

| 種類 | グループ数 | 例 |
|---|---|---|
| **PP の係り先** | 880 | `I eat an apple in the park.`<br>公園で食べる / 公園にあるリンゴを食べる |
| **モダリティと否定の作用域** | 160 | `I can not eat an apple.`<br>食べられない（¬◇） / 食べないでいられる（◇¬） |

等位接続の位置・入れ子、否定の作用域（節 vs VP）、限定詞、時制・相は
**すべて英語が区別している**。

### 日本語との比較

同じ 3,700 個の AST から:

| | 相異なる表層 | 衝突に関与する AST |
|---|---|---|
| 英語 | 2,620 | 2,080（56%） |
| **日本語** | **1,455** | **3,140（85%）** |

日本語は限定詞・時制相・否定の作用域・等位接続の**すべての軸**で潰れ、
最大12個の AST が1つの文になる。**英語のほうが曖昧さが少ない。**

ただしこれは日本語という言語の性質と、日本語レンダラーの未熟さ（過去完了と
単純過去を区別しない等）が混ざった数字であり、切り分けていない。

### 方法上の限界（重要）

この数字は**ツールが表現できる範囲内**の話である。AST が2つの読みを区別して
持てない曖昧さは、そもそも衝突として現れない。

- 量化子の作用域（"Every student read a book"）
- 語の多義性（bank, light）
- 照応（"John told Bill he was wrong"）
- 形容詞の作用域（"old men and women"）

そして英語レンダラーは**直近の改修で曖昧さを減らす方向に動いている**
（等位接続での主語の繰り返し、correlative による範囲明示）。
つまりこの実験は「英語がどれだけ曖昧か」ではなく、
**「良く書かれた英語がどれだけ曖昧か」**を測っている。

## Phase 1: 天井の測定（直接聞く）

Phase 0 の衝突から、原因の種類ごとに6件ずつ計18件を選び、**英語だけ**を与えて
「この文には構造的な解釈が何通りあるか」と直接聞いた。

| 種類 | 検出 |
|---|---|
| PP の係り先 | 6/6 |
| モダリティ否定 | 6/6 |
| 両方 | 6/6 |
| **合計** | **18/18（100%）** |

数の水増しではない。挙げた読みは意図した2つと正確に一致し、さらに私が列挙して
いなかった真の曖昧さ（`all` の作用域、`or` の作用域、否定呼応）まで正しく指摘した。

> 「in the park」が動詞句を修飾 — 私は公園でリンゴを食べる
> 「in the park」が名詞句 "an apple" を修飾 — 私は公園にあるリンゴを食べる

**事前登録の打ち切り条件B に抵触する。** 「検出率が高いなら AI が聞き返せば済む」。

---

## Phase 2-F: 現実的なタスクではどうか

しかし現実の使用で「解釈は何通りですか」と聞く人はいない。ただ文を渡して仕事をさせる。
そこで同じ18件を**翻訳タスク**として渡した。曖昧さについては一切触れない。

翻訳は必ずどちらかの読みに倒す必要がある作業なので、黙って選ぶか指摘するかが出る。

採点は LLM に行わせた。**対立する読みを明示的に与え**、それに言及したかだけを判定させる。
最初は正規表現で「曖昧」「解釈」等を拾ったが、応答が触れているのが**別の曖昧さ**
（can の能力/許可、否定の焦点、丁寧度）であるケースを取りこぼしていたため。

| 種類 | 意図した読みに言及 | （粗い正規表現判定） |
|---|---|---|
| **PP の係り先** | **0/6** | 1/6 |
| モダリティ否定 | 2/6 | 5/6 |
| 両方 | 1/6 | 5/6 |
| **合計** | **3/18（17%）** | 11/18 |

PP の係り先は**一度も**代替の読みを出さず、毎回「公園で」（動詞句への係り）を
黙って選んだ。Phase 1 で直接聞けば正しく2つ挙げた、まさにその読みである。

```
Phase 1（直接質問）: 「公園にあるリンゴを食べる」という読みもある  ← 正しく指摘
Phase 2（翻訳）:     私は公園でリンゴを食べます。                  ← 黙って選択
```

**能力はある。発動しない。** これが英語の曖昧さの主要な種類（880/1000 グループ）で起きている。

---

## Phase 2-F-instructed: 一言指示すれば足りるか

同じ翻訳タスクに、次の一行を足しただけ。

```
If the sentence has more than one possible structural reading, point that out before translating.
```

| 種類 | 指示なし | **指示あり** |
|---|---|---|
| **PP の係り先** | 0/6 | **6/6** |
| モダリティ否定 | 2/6 | 4/6 |
| 両方 | 1/6 | 4/6 |
| **合計** | **3/18（17%）** | **14/18（78%）** |

**主要な曖昧さ（PP の係り先、880/1000 グループ）は一行で完全に回復する。**

残る 4/18 はモダリティの作用域だが、これは失敗と呼びにくい。
`I can not eat an apple.` の ◇¬ 読み（「食べないでいられる」）は言語学的には実在するが、
実際の使用ではまず現れない。モデルが優先度を下げるのは**むしろ正しい**振る舞いである。

## 判定

事前に固定した表に照らす。

| 事前登録した条件 | 該当 | 結論 |
|---|---|---|
| A が最初から高い | — | 該当せず（英語だけでは 17%） |
| **F が B と同等** | **該当** | **不要。AI が聞き返せば済む** |
| D が B と同等以上 | 未実施 | — |
| E が B と同等 | 未実施 | — |

D・E・C は実施していない。**F の時点で判定が確定したため。**
決定的な条件が否定的に出たあとで他の条件を探すのは、計画で避けると決めた
「肯定を探しにいく」振る舞いそのものなので行わない。

B（英語 + LinguaScript）も実施していない。主要な種類で F が既に 6/6 に達しており、
**B はそれを超えられない**ので、走らせても優位は示せない。

---

## 得られたもの

否定的な結論だが、副産物のほうが使える。

### 1. 「AI は黙って選ぶ」は実測できた

能力 100%、自発 17%。この差は本物で、しかも**英語の主要な曖昧さで最大**（0/6）。

実用的な教訓は LinguaScript ではなく**プロンプト**にある。
「曖昧なら指摘して」の一行は、コストがほぼゼロで効果が大きい。
これはこのツールを使わなくても誰でも使える知見である。

### 2. 良い英語は思ったより曖昧でない

構造的曖昧さは PP の係り先とモダリティ作用域の2種類しかなかった。
等位接続・否定の作用域・限定詞・時制相は英語が区別している。

ユーザーの仮説「適切な単語と適切な構造を選べばすべての曖昧さは消える」は、
**少なくとも構造については支持された**。そして LinguaScript はそれを安く済ます
手段ではなかった。一行の指示のほうが安い。

### 3. 日本語のほうがはるかに曖昧

同じ 3,700 AST から、英語は 2,620 通り、日本語は 1,455 通り。
LinguaScript の価値があるとすれば英語よりも**日本語側**である。
ただしレンダラーの未熟さと言語の性質が混ざった数字で、切り分けていない。

### 4. 価値は「符号化」ではなく「可視化」かもしれない

Phase 0 の衝突一覧は、LLM に一度も渡さずに作れた。
「この文型のここが曖昧」を機械的に列挙できることは、それ自体が英語教材の素材になる。

つまりこのツールの使いどころは
**「曖昧さを AI に伝える」ではなく「曖昧さを人間に見せる」**側にある可能性がある。
これは元々の出自（英文法の可視化）に戻るということでもある。

---

## この結論の限界

- **ツールが表現できる曖昧さしか測っていない。** 量化子の作用域、語の多義性、照応は
  AST が持てないので衝突として現れない。英語全体の曖昧さを測ったわけではない
- **「良く書かれた英語」を測っている。** レンダラーは直近の改修で曖昧さを減らす方向に
  動いており、人間が書く雑な英語はもっと曖昧なはず
- **モデルは1つ（Claude）、各条件1回。** 温度による揺れを見ていない
- 判定に LLM を使っている。**生の応答は `experiments/out/phase*.json` に全部残してある**ので
  人手で監査できる（Phase 0 の衝突一覧は決定的かつ LLM 不要で再生成できるため追跡していない。
  下の再現手順の1行目で作られる）
